이 명령어는 `dddd/js/questions.js`를 대상으로 아래 7단계 루틴을 순서대로 실행한다.

**중요 원칙**: 각 단계는 바로 이전 단계가 성공해야 진행한다. 어느 단계든 아래 "실패 조건"에 해당하면 그 즉시 이후 단계를 진행하지 않고 중단하며, 어느 단계에서 왜 실패했는지를 구체적으로(대상 id·필드·값 등) 보고한다.

대상 카테고리 강제 지정: $ARGUMENTS

- 비어 있으면 3단계에서 가장 보강이 필요한 카테고리를 자동으로 선정한다.
- 값이 있으면 해당 카테고리로 강제 지정한다. 존재하지 않는 카테고리(한국사/과학/지리/스포츠 외)가 지정되면 사용 가능한 카테고리 목록을 안내하고 중단한다 — 이것도 실패로 간주해 이후 단계를 진행하지 않는다.

---

### 1단계 — 파일 구조 읽고 이해하기

- `dddd/js/questions.js` 전체를 읽는다.
- 확인: `QUESTIONS` 배열이 존재하는가, 각 항목이 `id`/`category`/`difficulty`/`question`/`options`/`correctAnswer`/`explanation` 7개 필드를 모두 갖는가, `options`가 4개 원소 배열인가, `correctAnswer`가 0~3 범위인가.
- **실패 조건**: 파일을 읽을 수 없음 / `QUESTIONS` 배열을 찾을 수 없음 / 위 구조를 벗어나는 항목이 하나라도 있음.
- 실패 시: 문제가 된 항목의 `id`와 어떤 필드가 어떻게 어긋났는지 명시하고 중단한다.

### 2단계 — 현재 문제 개수와 분포 확인

- 전체 문제 수, `id`의 최소~최대 범위, `id` 누락·중복 여부를 확인한다.
- 카테고리별 문제 수, 카테고리 × 난이도(easy/medium/hard) 교차 분포, `correctAnswer` 인덱스(0~3) 분포를 집계한다.
- **실패 조건**: `id` 중복 발견 / 정의된 4개 카테고리(한국사·과학·지리·스포츠) 외의 값 발견.
- 실패 시: 중복된 `id` 목록 또는 비정상 카테고리 값을 구체적으로 제시하고 중단한다.

### 3단계 — 카테고리별 부족한 부분 파악

- 2단계 결과를 바탕으로 카테고리마다 다음을 평가한다: 총 문제 수, 비어 있는 난이도 유무, hard 문제 비율이 다른 카테고리 평균보다 뚜렷이 낮은지, `correctAnswer` 인덱스 분포가 특정 값으로 쏠려 있는지.
- 이를 종합해 "가장 보강이 필요한 카테고리"와 그 안에서 "가장 필요한 난이도"를 하나씩 정한다.
  - 동률 시 우선순위: ① 총 문제 수가 더 적은 카테고리 → ② hard 문제 수가 더 적은 카테고리 → ③ 정의 순서(한국사 > 과학 > 지리 > 스포츠)상 앞선 카테고리.
  - 난이도 선정도 동일하게: 비어 있는 난이도가 있으면 그것을 최우선으로, 없으면 비율이 가장 낮은 난이도를 선택한다.
- $ARGUMENTS로 카테고리가 강제 지정된 경우 카테고리 선정 단계는 생략하고, 그 카테고리 안에서 부족한 난이도만 위 기준으로 정한다.
- **실패 조건**: 2단계 결과가 비어 있어 평가할 대상이 없음.
- 실패 시: 사유를 보고하고 중단한다. (모든 카테고리가 이미 완벽히 균형 잡힌 경우는 실패가 아니다 — 이때는 총 문제 수가 가장 적은 카테고리를 기본값으로 선택해 계속 진행한다.)
- 선정된 카테고리·난이도와 그 근거를 보여준다.

### 4단계 — 새 문제 추가 전 중복 체크

- 3단계에서 정해진 카테고리·난이도에 맞는 새 문제 1개를 초안으로 작성한다. `pros/4.pro.md` 교차검증 가이드라인(정답 유일성, 최상급 표현의 측정 기준 명시, 시간 민감 사실의 기준 시점 명시, 신뢰할 수 있는 사실만 사용)을 따른다.
- 초안의 `question`을 기존 전체 문제의 `question`과 비교해 완전히 동일하거나 사실상 같은 소재를 다루는 문제가 있는지 확인한다.
- 중복이면 다른 소재로 최대 2회까지 다시 초안을 작성해 재확인한다 (최초 1회 + 재작성 2회 = 총 3회).
- **실패 조건**: 3회 시도 모두 기존 문제와 중복됨.
- 실패 시: 중복된 기존 문제의 `id`와 문제 텍스트를 근거로 제시하고 중단한다. (이 시점까지는 파일을 수정하지 않으므로 되돌릴 것이 없다.)
- 중복 없는 초안이 확정되면, 파일에 적용하기 직전의 원본 내용을 스냅샷으로 남긴다 (5단계 검증 실패 시 롤백용 — 6단계의 사용자용 백업과는 별개다).
- 확정된 초안을 해당 카테고리 블록의 마지막 항목 뒤에 추가한다. 기존 항목의 형식·들여쓰기·트레일링 콤마 스타일을 그대로 따르고, `id`는 기존 전체 최대값 + 1로 지정한다.

### 5단계 — 문제 추가 후 형식 검증

- 파일을 다시 읽어 방금 추가한 항목을 확인한다.
- 확인: `id`가 유일하고 기존 최대값+1인가 / `category`가 유효한 4개 카테고리 중 하나인가 / `difficulty`가 easy·medium·hard 중 하나인가 / `options`가 정확히 4개 원소인가 / `correctAnswer`가 0~3 범위이며 `options[correctAnswer]`가 실제로 맞는 답인가 / `explanation`이 비어 있지 않은가 / 트레일링 콤마 등 문법·스타일이 기존 항목과 일치해 파일이 유효한 JS 배열로 유지되는가.
- **실패 조건**: 위 확인 사항 중 하나라도 어긋남.
- 실패 시: 4단계에서 남긴 스냅샷으로 파일을 즉시 원상 복구(추가 전 상태로 롤백)하고, 무엇이 왜 실패했는지 구체적으로 보고한 뒤 중단한다.

### 6단계 — 전체 데이터 백업

- 5단계까지 통과한 최종 `dddd/js/questions.js`를 `dddd/backups/questions.js.<YYYYMMDD-HHMMSS>.bak.js` 형태로 복사해 백업한다 (`dddd/backups/` 폴더가 없으면 새로 만든다).
- **실패 조건**: 백업 폴더 생성 실패 또는 파일 복사 실패.
- 실패 시: 오류 메시지를 그대로 보고하고 중단한다. 이때 5단계까지 검증을 통과한 문제는 이미 파일에 정상 반영되어 있다는 점, 즉 데이터 자체는 문제없고 백업 생성만 실패했다는 점을 함께 안내한다.

### 7단계 — 실행 결과 상세 보고

다음을 포함해 보고한다.

- 추가된 문제 전체: `id`, `category`, `difficulty`, `question`, `options`, `correctAnswer`(보기 텍스트 포함), `explanation`.
- 3단계 선정 근거: 왜 이 카테고리·난이도를 골랐는지.
- 4단계 중복 체크 결과: 몇 번째 시도에서 확정됐는지, 비교한 기존 문제 수.
- 추가 전/후 비교표: 카테고리별 총 문제 수, 난이도 분포, `correctAnswer` 인덱스 분포 (2단계 스냅샷 vs 최신 상태).
- 6단계 백업 파일 경로.
- 1~6단계 각각의 통과 여부(✅/❌) 체크리스트.
