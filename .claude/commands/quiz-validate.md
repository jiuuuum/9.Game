이 프로젝트의 퀴즈 문제 데이터(`dddd/js/questions.js`)를 점검한다.

대상 카테고리: $ARGUMENTS

- $ARGUMENTS가 비어 있으면 전체 문제(모든 category)를 검증 대상으로 한다.
- $ARGUMENTS에 값이 있으면 그 값을 category로 사용해 해당 카테고리(예: 한국사, 과학, 지리, 스포츠)의 문제만 검증 대상으로 한다. 존재하지 않는 카테고리가 지정되면 사용 가능한 category 목록을 보여주고 중단한다.

1. 검증 대상 문제들의 `question`과 `explanation` 필드에서 "가장", "최초", "최고", "최대", "제일" 등 최상급/모호한 표현을 찾는다.
2. 찾은 각 문제에 대해 `pros/4.pro.md` 가이드라인 기준으로 다음을 확인한다.
   - 측정 기준이 명시되어 있는가? (예: "면적 기준으로", "2024년 기준", "676년")
   - 기준이 없어도 되는 경우인가? (다른 해석의 여지가 없어 모호하지 않은 경우 — 예: "태양에 가장 가까운 행성"은 거리 기준 외 해석이 불가능하므로 기준 명시 불필요)
   - 시간에 따라 바뀔 수 있는 사실인데 기준 시점이 빠져 있지 않은가?
   - 영토·지리적 범위가 모호한 채로 쓰이지 않았는가? (예: 남북한 실효 지배 범위 문제)
3. id, category, 문제 텍스트, 매칭된 표현, 기준 명시 여부(✅ 명시됨 / ⚠️ 불명확 / — 불필요)를 표로 정리해서 보여준다. ⚠️로 표시한 항목에는 어떤 기준(예: 면적/영토/인구/시점 등)을 명시해야 하는지 함께 적는다.
4. 기준이 빠졌거나 모호한 문제가 있으면 구체적인 수정 문구를 제안한다. 사용자가 승인하기 전까지는 파일을 직접 수정하지 않는다.
