이 프로젝트의 퀴즈 문제 데이터(`dddd/js/questions.js`)에 새 문제를 추가한다.

카테고리: $1
난이도: $2

- $1 또는 $2가 비어 있으면 올바른 사용법(`/quiz-add <카테고리> <난이도>`)을 안내하고 중단한다.
- $2는 `easy`, `medium`, `hard` 중 하나여야 한다. 그 외 값이면 사용 가능한 난이도 목록을 안내하고 중단한다.
- 파일을 읽어 기존에 쓰인 category 값(예: 한국사/과학/지리/스포츠) 목록을 확인한다. $1이 기존 카테고리와 일치하지 않으면, 새 카테고리를 만드는 것이 맞는지 사용자에게 확인한 뒤 진행한다.

1. 파일 전체를 읽어 현재 존재하는 최대 `id` 값을 확인하고, 새 문제의 `id`는 `최대id + 1`로 정한다.
2. 같은 category의 기존 문제들을 확인해 주제가 겹치지 않는 새로운 문제를 하나 만든다. 다음 형식을 정확히 따른다 (`js/questions.js`의 기존 항목과 동일한 필드 구조):
   ```js
   {
     id: <번호>,
     category: "<카테고리>",
     difficulty: "<난이도>",
     question: "<문제>",
     options: ["<보기1>", "<보기2>", "<보기3>", "<보기4>"],
     correctAnswer: <0~3 인덱스>,
     explanation: "<해설>",
   }
   ```
3. `pros/4.pro.md` 교차 검증 가이드라인을 반드시 지켜서 문제를 작성한다.
   - 정답이 하나로 명확한가? 다른 해석의 여지가 있다면 문제나 보기에 기준(예: "면적 기준으로", "2024년 기준")을 명시한다.
   - "가장", "최초", "최대" 등 최상급 표현을 쓸 경우 측정 기준을 명시한다 (해석의 여지가 없는 경우는 예외).
   - 시간에 따라 바뀔 수 있는 사실은 기준 시점을 명시한다. 지리적·분류적 범위도 모호하지 않게 한정한다.
   - 확실치 않은 사실은 실제로 알고 있는 신뢰할 수 있는 정보로만 작성한다. 의심스러우면 해당 문제를 만들지 말고 다른 주제로 대체한다.
4. `correctAnswer` 인덱스는 가급적 0~3 중 기존 문제들의 분포가 한쪽으로 치우치지 않도록 고려해서 정한다 (예: 특정 인덱스가 이미 과도하게 많다면 다른 인덱스를 우선 고려).
5. 작성한 문제를 사용자에게 보여주고 승인을 받은 뒤에만 파일을 수정한다. 승인 전에는 파일을 변경하지 않는다.
6. 승인되면 해당 category 블록의 마지막 항목 뒤에 새 문제를 추가한다 (기존 항목들의 형식·들여쓰기·트레일링 콤마 스타일을 그대로 따른다). 기존 문제의 `id`나 순서는 변경하지 않는다.
7. 수정 후 추가된 문제의 `id`, `category`, `difficulty`, `correctAnswer`를 요약해서 보여준다.
