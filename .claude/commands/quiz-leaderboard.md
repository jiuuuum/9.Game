이 프로젝트의 퀴즈 문제 데이터(`js/questions.js`)를 카테고리 단위로 채점해 순위표를 만든다. (게임 내 플레이어 순위/기록이 아니라, 문제 은행의 카테고리별 구성 품질을 순위화하는 관리용 리포트다.)

정렬 기준: $ARGUMENTS

- $ARGUMENTS가 비어 있으면 `score`(종합 점수) 기준으로 정렬한다.
- `count`면 총 문제 수, `balance`면 균형 점수만 기준으로 정렬한다. 그 외 값이면 사용 가능한 정렬 기준(score/count/balance)을 안내하고 중단한다.

1. 파일을 읽어 카테고리별로 다음을 집계한다.
   - 총 문제 수
   - 난이도(easy/medium/hard)별 문제 수
   - `correctAnswer` 인덱스(0~3)별 문제 수
2. 카테고리마다 다음 두 가지 하위 점수를 계산한다 (0~100점, 계산 근거를 함께 밝힌다).
   - **커버리지 점수**: 총 문제 수와 난이도 3종이 모두 존재하는지를 반영 (문제 수가 많고 난이도가 고르게 있을수록 높음, 특정 난이도가 0개면 크게 감점).
   - **균형 점수**: `correctAnswer` 인덱스 분포가 얼마나 고른지를 반영 (이상적으로는 0~3 인덱스가 각각 25%에 가까울수록 높음, 한 인덱스로 쏠릴수록 감점).
   - **종합 점수** = (커버리지 점수 + 균형 점수) / 2
3. 지정된 정렬 기준으로 카테고리를 순위화해 리더보드 표로 보여준다: 순위, 카테고리, 총 문제 수, 난이도 분포(easy/medium/hard), 정답 인덱스 분포(0/1/2/3), 커버리지 점수, 균형 점수, 종합 점수.
4. 최하위 카테고리에 대해 순위가 낮은 구체적 원인(예: hard 난이도 부재, 정답이 인덱스 2에 60% 쏠림)과 개선 방향(예: `/quiz-add`로 특정 난이도·정답 위치를 노려 문제 추가)을 짚어준다.
5. 1위 카테고리도 어떤 점에서 잘 갖춰져 있는지 한 줄로 언급한다.
6. 파일을 수정하지 않는다 — 순위표와 분석만 보고한다.
